# 维护规则与证据索引

日常操作统一使用 [开发说明](DEVELOPMENT.md)、[来源规范](../tools/chinese-maintainer/SOURCE_LOOKUP.md) 和 [发布说明](../tools/subscriber/NETWORK.md)。本页汇总维护政策、数据范围和可核对的证据；操作不再按日期文档选择不同流程。

## 发布入口

源码、下载、Releases 和监控统一在 `1996Neil/mtga-chinese-updates`。当前下载入口由根目录 `download.json` 指定；监控配置、公开下载验证与安装包 profile 使用相同渠道和公钥，不手工改写已签名的 feed 文件。

正式发布使用 stable 和绑定候选的验收记录。testing 只用于明确的测试发布，不能替代正式验收。资源版本用于匹配游戏和复查证据，不代表还需要维护另一套源码或操作入口。

签名清单、Release 附件、来源快照及固定审查记录保持原字节；文档和可执行流程统一到当前路径。没有新文本或资源变化时，复用已有证明不能被描述为做过新的游戏测试。

## 一键维护更新

### 日常轻量路径

热缓存下的自动处理目标是五分钟以内，使用现成 `maintain`，不在每次维护时重新设计或修复整个系统。先确认输入是否变化，再选择最小工作：

| 情况 | 执行范围 |
| --- | --- |
| 游戏、代码、Git 数据与候选输入未变 | 复用候选和已有独立审查，执行所需机器完整性检查并接续当前验收或发布阶段 |
| 仅译文或部分资源变化 | 处理受影响项；复用影响输入完全一致的资源、来源缓存和证明 |
| 新游戏资源世代 | 取证、比对新增/英文及身份用途变化，构建受影响资源，明确列出补验收范围 |
| 首次检出、网络失败、大批新译文或需要真实游戏验收 | 单独列出耗时及待办；不能将其说成五分钟内可完成的常规发布 |

常规运行不重新下载锁定且校验有效的数据、不重新编译未变化的客户端、不重新导出全库、不人工重审未变化文本。全套工程回归测试用于工具代码变更，正常维护保留发布所需的资源、签名、哈希和准入检查。遇到大量新增内容，不扩展为全库审校，也不能将未知卡名或规则默认为已通过。

2026-11-05 的一次真实热缓存运行耗时 **33.44 秒**：复用现有 65.0 候选，完成机器检查后停在真实游戏验收和发布验收门槛；未重建资源、未发布、未安装。这个测量不代表新版本构建、译文审查、联网分发或游戏验收能在同样时间内完成。汇报应区分自动运行耗时、实际发布结果和剩余人工工作，不因达到时限就伪造完成。

### 统一命令与阶段

对维护 Agent 说“一键维护更新”，即授权执行从适配到 stable 发布及验证的完整维护工作。Agent 不应只运行玩家端检查，然后要求用户等待自己发布。日常执行：

```sh
./bin/mtga-cn maintain --online
```

这是可接续的维护编排器。线上模式从公共源码的 `maintenance-source.json` 锁定私有数据仓库、精确提交、子目录和 manifest 指纹；首次自动 clone，随后验证缓存与 Git 状态，只使用已锁定内容。它准备客户端与安装包缓存、配置及新的隔离 Registry，不依赖已删除的旧本地数据库或审校目录，也不修改旧状态。默认配置已是线上模式后，日常只需 `./bin/mtga-cn maintain`。

编排器保存当前游戏版本、输入指纹、执行阶段、候选目录、修订、冻结发布绑定和具体阻塞；同一命令重跑会重验并接续，不把“生成候选”显示为“已发布”。新游戏版本从 r1 起算；同一完整游戏版本与 Steam build 从已签索引及所有已有 Release（包括草稿）的最大修订加一。上传/推进索引失败后继续原冻结包，不另造修订。

| 阶段 | Agent 自动完成 | 必须保留的门槛 |
| --- | --- | --- |
| 当前输入 | 同步锁定的 Git 文本输入，检查游戏、Steam build、活动 manifest；验证本模式 Registry 实际登记的源文件 | 线上模式使用新状态，旧 Registry 不删除；旧备份不是新官方底稿 |
| 官方底稿 | 用当前 Steam depot 缓存、CodeResources 和官方英文库采集五层原字节 | 新捕获需要独立来源审查后登记；采集器不自行批准 |
| 增量适配 | 调用既有 update，复用候选、上下文匹配的便携社区文本和字体资源缓存；用真实旧英文及身份计算差异 | 人工/语义审查只处理新增、英文/身份/用途变化、来源失效和冲突；便携中文不升级为历史已审批准；机器完整性检查保留 |
| 发布前 | 重验当前候选、独立工程审查、发布验收绑定和正式客户端 HTTPS 重建证据 | 旧真实验收仅在其绑定范围和资源字节匹配时复用；变化则明确补验收 |
| 发布与验证 | 复用现有密钥、公钥、协议和安装包；调用统一 stable 发布器；同步公开监控种子；验签并核对全部匿名资源、安装包和正式客户端预演 | 不覆盖历史 Release/签名，不自动安装到游戏；所有检查完成才报告发布完成 |

快速维护不是取消检查。未变化译文不重新人工逐条审校，已验证且影响输入一致的字体/界面资源不重复生成；已有候选的 update 复用路径继续生效。维护资料不能存放在会被清理的临时目录后再当作永久缓存；Registry、来源快照、官方底稿、验收与审查是后续增量维护的输入，清理前应保留可恢复的原字节备份。

本地配置格式为 `MTGA_CN_MAINTENANCE_CONFIG_V1`，位置默认 `~/Library/Application Support/MTGAChineseMaintainer/maintenance.json`，由线上准备器自动生成，不入 Git。它记录 `online:true`、Git 提交、`portable_root`、`portable_manifest_sha256`、隔离 `state_root` 和客户端/公钥/安装包缓存路径。可选当前 `run`、`acceptance`、`network_acceptance`。所有路径使用绝对路径；`key_file` 只指向本机现有发布私钥，不保存或输出私钥内容。私有仓库访问沿用已登录的 GitHub CLI，配置不包含 Token。不再把旧个人路径和旧历史文件列为线上维护前提。

未指定 `run` 时 update 自动构建或复用当前候选；验收默认查找候选中的 `publisher-acceptance.json`。发布前联网证据默认是候选中的 `network-acceptance.json`，格式 `MTGA_CN_NATIVE_NETWORK_ACCEPTANCE_V1`，必须包含 `status:"PASS"`、`anonymous_https:true`、`native_reconstruction:true`、实际 `client` 指纹、绑定原始 publisher subject 的 `subject_sha256`、五层 `outputs` 指纹，以及非空 `evidence_files`（原始预演日志/输出的绝对路径到哈希/大小映射）。原生客户端不会自行输出这一汇总格式；维护 Agent 在实际正式客户端联网预演后，从原始日志和逐层复读结果生成记录，不能因为需要发布而自动填写通过。发布后会再次使用正式客户端在隔离的官方输入副本上预演，重建文件逐层复读，真实游戏不变。

遇到阻塞时，Agent 应先完成不依赖阻塞项的资料查找、取证或独立审查，并报告当前版本、已完成阶段、缺的具体证据和接续记录。网络失败保留待重试状态；线上锁定数据变化则恢复锁定提交，不能替换 manifest 哈希绕过守卫。旧本地来源被删除时不得修改其历史证明；优先接续独立的线上模式，不能将本地数据丢失包装成“新版不兼容”。需要真实游戏验收时只列本次资源变化对应项目，不声称旧版测试已覆盖新版本。

## 名称英文、内容中文

- `Events/Event_Title_*`、`Events/Event_Cat_*`、双层 `Events/Events/` 下同类字段，以及 `Formats/Format_Title_*` 使用当前官方英文。
- Desc、Description、Body、Instructions、Tooltip 等介绍字段继续采用已审中文，即使路径中有 Title。普通导航标题、卡名、类型和关键词不按赛事名称处理。
- 名称内本地化引用按当前官方英文递归展开，保留法术力图标等标签。缺少引用或循环引用停止构建；不改写介绍等位置共享的中文引用目标。
- 显示政策不删除中文候选或来源证据。实际逻辑在 `registry.py`，隔离修正工具为 `event_names.py`。

2026-10-24 的精确差分证据：核对 1,464 个名称字段，恢复 28 个中文名称并展开 33 个引用，共 61 个变化；其余 20,330 个非名称字段、其他语言、表及资源层不变。另一个初筛 Title 字段是 MWM 介绍，保留中文。候选验证不代表当时已应用到游戏。
