# MTGA 中文读牌浮窗

原生卡牌及牌表保留英文。展开英文卡牌大图时，这个独立 macOS 浮窗显示中文牌名、类型和规则，关键词标题与解释只显示中文。浮窗省略背景描述，游戏原有英文背景描述保持原样。没有修改 MTGA 资源、客户端、套牌、收藏或语言设置。

双击桌面 `MTGA 中文读牌.command` 启动。首次使用点击浮窗里的“开启屏幕录制权限”，在 macOS 设置中允许 **MTGA 中文读牌**，然后退出并重新打开。切回 MTGA，悬停卡牌以展开原生大图。点击“字号”可用滑块或按钮调整正文大小（14–36），重开应用会记住字号；背景透明度保持原样。窗口可拖动或“换一侧”；“固定”保留当前牌，“暂停”停止识别，“退出”结束进程。关闭窗口也会停止识别，可从菜单栏“读牌”重新显示。

识别只读取前台 MTGA 的窗口；ScreenCaptureKit 截图和 Vision OCR 均在本机内存处理，不保存、上传截图，不操作游戏。显示的是本机卡库的牌面规则和印刷数值，不读取战场实时修改。游戏需要继续保持英文，供标题识别。

中文来自现有本地汉化资料。只有同一 LocId 的供体英文与当前英文内容一致，且供体包含中文时才采用译文；不匹配、混合英文或包含未解析内部模板的规则在浮窗中显示中文缺译提示，请查看游戏原文。类型和关键词也检查混合英文及未替换占位符，缺译时显示中文提示。同名但规则不同的卡暂不自动匹配。浮窗不显示背景描述，原生英文描述仍在游戏中。关键词覆盖取决于匹配的本地资料，未匹配的关键词不生成解释。

游戏资源更新会锁定当前浮窗，普通“继续”不能解除。双击桌面 `更新浮窗卡牌.command` 更新读牌资料，然后退出并重新打开应用。无需改动游戏或重新编译 App。

## 识别流程与延迟

当前实现先读英文大卡，再查本机中文资料。下面说明实际识别流程，以及哪些等待属于处理耗时、哪些属于没有识别成功。

1. **游戏先展开大图。** 浮窗没有接入 MTGA 的鼠标悬停事件，也不直接取得游戏内部卡牌编号；它靠定时读取画面发现大卡。它识别的是英文文字，不是根据卡牌插画猜牌。
2. **检查能否读取。** 每 150 毫秒尝试一次；上一轮未结束时跳过，避免任务堆积。仅在 MTGA 位于前台、已授权、浮窗可见且没有暂停或固定时继续。鼠标进入读牌浮窗时保留当前牌并停止扫描，方便调整字号和阅读。
3. **截取游戏窗口。** 只捕获 MTGA 窗口，输出宽度最多 1600 像素，不包含鼠标。窗口列表缓存 3 秒，减少重复查找；截图仅在本机内存使用。
4. **识别英文标题并核对正文。** 使用 macOS 自带 Vision 的准确 OCR。首次识别扫描整个游戏窗口；找到大卡后优先扫描上次大卡所在区域。标题必须与本机卡库中的唯一牌名匹配，匹配时忽略大小写、重音和标点。还要求标题足够大、OCR 置信度至少 0.60，并在其下方找到该牌规则中最多 3 个不同的英文词作为证据；没有规则词的地牌通过类型文字核对。单独的牌表名称条目不触发翻译。
5. **查中文并显示。** 成功后读取本机已有中文牌名、类型、规则及关键词解释，不逐次请求网络翻译。识别过程中若鼠标移动达到 16 个屏幕点，或切出了游戏，就丢弃该轮结果，避免快速换牌时显示过时内容。中文资料未通过校验时显示中文缺译提示。

可见延迟大致由这些部分组成：**游戏展开大图的等待 + 等到下一轮扫描 + 截图 + OCR 和文字校验 + 浮窗更新**。其中有几个容易混淆的地方：

- **150 毫秒是尝试间隔，不是总响应时间。** 空闲时仅定时调度通常要等 0–150 毫秒；如果上一轮仍在处理，还要等它结束后的下一次机会。截图和 OCR 的时间另外计算。
- **切换大卡位置可能多等一轮。** 优先扫描旧区域找不到时，需要整窗兜底；整窗兜底机会以约 700 毫秒间隔限制，避免每轮重复做两次 OCR。这可能推迟发现新位置的大卡，并非每张牌都固定等待 700 毫秒。
- **持续移动鼠标会丢弃结果。** 程序没有固定“悬停若干秒”的计时，但为了防止错牌，截图到识别结束之间鼠标移动过多会使这轮无效，需要停稳后再识别。
- **有些等待其实是匹配失败。** 当前标题高度必须达到整张截图高度的 2.3%；较小的游戏大图也可能被挡在这个阈值外。标题 OCR 错字、正文被遮住、规则证据不足、卡库缺牌或同名不同规则，都可能持续不出结果。单纯缩短扫描间隔不能解决这些问题。
- **前台、权限和资料状态会直接阻止扫描。** 系统设置或其他应用位于前台、鼠标位于浮窗、应用暂停或固定、权限未生效、游戏资源已变更时，都不会进行正常自动读牌。这些属于状态限制，不应当解释为 OCR 很慢。

两张已有用户截图各测 5 次，预热后的 OCR 中位数约为 119 和 137 毫秒；它们只是离线识别耗时，不能代表真实悬停到中文出现的时间。目前已恢复当前安装版本的屏幕读取授权，但尚未取得连续实机悬停识别成功的验证结果，也没有测得端到端延迟。后续排查需要分别记录截图耗时、OCR 耗时、匹配失败原因和结果被丢弃的原因，才能确定真实瓶颈。

开发命令：

```sh
zsh tools/card-overlay/build.sh
python3 -m unittest discover -s tools/card-overlay -p 'test_*.py' -v
python3 tools/card-overlay/install.py  # 首次安装；已有 App 会拒绝覆盖
python3 tools/card-overlay/upgrade.py  # 先退出读牌；保留完整旧 App 备份后升级
```

使用 macOS 自带 AppKit、SwiftUI、ScreenCaptureKit、Vision 和 CryptoKit；没有新增第三方运行时依赖。首次安装脚本拒绝覆盖已有 App 或桌面入口；升级脚本只替换已登记的本项目 App，保留旧版备份，不替换外部卡牌资料或桌面入口。App 不加入登录启动项；移除桌面入口、`~/Applications/MTGA 中文读牌.app` 和 `~/Library/Application Support/MTGA Card Reader` 即可移除本次安装。历史备份与游戏目录无需改动。

验证记录在 `compatibility/card-language-2026-10-07/verification.json`。构建、真实截图 OCR、原生界面渲染与连续实机悬停是不同证据；以记录中的实际验收状态为准。
