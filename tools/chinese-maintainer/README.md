# MTGA 中文汉化与双语导入维护工具

普通用户的首次安装、邮件订阅、后续更新与故障处理见：[用户订阅与更新完整流程](SUBSCRIBER_FLOW.md)。

维护者与 Agent 补译／纠错前必读：[来源查询与逐项核对规范](SOURCE_LOOKUP.md)；自动工作入口见 [AGENTS.md](AGENTS.md)。现成中文、社区 Oracle、概念依据与 AI 表达必须分别记录，不以 AI 复核代替网络来源核实。

日常使用先看下面的桌面操作流程；完整验收方法见“首次候选和后续新版本的真实验收”。后半部分供维护者查阅。

本项目现整合在公开仓库 `1996Neil/mtga-chinese-updates`。普通用户看根 README；源码构建、路径配置和本地资料依赖见 [开发说明](../../docs/DEVELOPMENT.md)。

历史 JSON、来源数据库与回滚记录保留原始字节，其中的旧绝对路径由受限映射解析；不要手工替换历史路径。迁移不改变现有 `trial` 状态。代码指纹变化会阻止旧候选再次安装，需重新构建并审查；诊断与回滚备份校验仍可执行，回滚继续检查游戏版本及当前资源。

## 双击桌面脚本后怎么操作

1. 等 Steam 更新完成，启动 MTGA，等游戏内资源下载完成，再完全退出游戏。
2. 选择 **2「检查新版官方底稿与备份」**。底稿是构建汉化所需、经过核验的原始资源。
3. 底稿检查通过后，选择 **3「构建并验证汉化候选」**。候选是待测试文件；构建不会安装到游戏。
4. 等候选静态检查和独立工程审查通过后，由维护者协助临时测试、记录真实游戏内验收。**当前菜单不自动完成这一步，按 4 也不能跳过。** 具体命令和验收清单见下文。
5. 验收记录通过后，退出 MTGA，选择 **4「正式安装／保留」**。

随时选 **1** 查看状态及最近失败原因；选 **6** 在终端显示中文操作指南。

### 如果按 3 报错

| 中文提示 | 原因 | 下一步 |
| --- | --- | --- |
| 尚未登记当前版本的可信界面／基础字体底稿 | 游戏版本超出维护器已核验的范围 | 请维护者核验并接入这一版本的官方资源，之后按 2 重新检查。重复按 3 无效，不要拿旧版备份顶替。 |
| 没有完整可用的候选 | 构建尚未成功 | 按 1 看失败原因，解决后再按 2、3；不要直接按 4。 |
| 静态检查或独立工程审查未通过 | 候选尚不能进入临时测试 | 请维护者处理报告列出的阻塞项。 |
| 当前候选的中文显示与导入待验收 | 静态检查不能替代游戏内测试 | 按 6 查看临时测试、五份牌表和验收记录步骤。 |
| 游戏版本或资源与原记录不一致 | 官方更新或其他资源变化导致旧记录不适用 | 按 2 检查；不要用旧备份覆盖新版游戏。 |
| 游戏仍在运行 | 无法安全替换文件 | 完全退出 MTGA 后重试。 |

**构建失败未安装资源，不需要为此回滚。** 选项 5 仅恢复最近安装／临时测试前的实际文件，不是撤销 Steam 更新。若安装或回滚中断，部分文件可能已变化，请保留现场、选 1 查看状态并交由维护者检查。

当前界面／基础字体的可信底稿固定为已审查的 `2026.64.50_20261020T202537160084Z` 捕获。其他版本需要单独适配；中文提示升级不会解除这个限制。

命令名、文件名和 JSON 字段保留原样，方便脚本兼容和排查；普通提示使用中文。`mtga-cn diagnose-base --human` 显示中文摘要，省略 `--human` 仍输出机器可读 JSON。命令加 `--details` 可显示原始错误。

这是独立的本地汉化维护器。每次使用新官方资源重建中文 F1 与英文 F0，分别报告中文显示、原生双语导入。不会使用旧数据库覆盖新版本，不会自动猜译，不修改官方 manifest、主程序、GameAssembly 或账号数据。

## 日常命令

```sh
mtga-cn status
mtga-cn update
mtga-cn install
mtga-cn rollback
```

`update` 保存新官方资源，比较版本、原文及字段用途，迁移可靠译文，合并已独立审查的 donor 补漏，重新生成名称变体，构建和复读五个资源层，生成 `report.json` / `REPORT.md`。没有新变化时复核已有候选。**这个命令不写游戏文件。**

`install` 要求两项静态 Validator PASS、没有高风险未知项、独立工程审查绑定当前代码和候选、当前版本候选的客户端验收 PASS，并且游戏已退出。一个能力失败或客户端尚未验证，默认拒绝安装。

`rollback` 恢复最近一次正式安装或临时测试**之前的实际文件**，不是固定旧版本。所有目标的 before、candidate、SHA256、长度、权限和官方 manifest 均保留。每次替换前再次检查进程及版本/哈希；未知变化拒绝覆盖。中断留下持久事务日志，退出游戏后重试 rollback 可恢复。本机历史恢复脚本仅更新维护环境路径，版本守卫和原始 manifest 均保留。

## 首次候选和后续新版本的真实验收

数据库检查无法运行 MTGA 内部的原生导入器；旧版本的用户 PASS 不会自动转移到新版本。目前没有已验证的无人值守原生导入驱动。因此两条日常命令已共享生成、检查与安装流程，但新候选仍需一次受控客户端验收，不能承诺以后每次完全无人操作。

当完整候选的静态检查及独立审查都通过后，用户明确接受临时测试，可退出游戏并执行：

```sh
mtga-cn test-session --begin
```

这会先保存本轮完整改前状态，再临时装入候选。它是临时测试状态，**不会把“已测试通过”写进报告**。不满意或任何检查失败，退出 MTGA 后 `mtga-cn rollback`。

打开游戏，语言保持 English / en-US，按当前运行目录 `fixtures/` 中的以下五个牌表分别测试原生导入，并各保存一次原生导出：

- `english-60.txt`：历史裸英文 60 张、22 个 TitleId。
- `chinese-60.txt`：同一牌组的中文名称。
- `mixed-60.txt`：同一牌组交替中英文。
- `qualified-60.txt`：历史印刷限定对照，按 TitleId 汇总数量，不强迫裸导入选择同一印刷。
- `special-english-60.txt`：新版每种非零 LinkedFaceType 各选一个主正面，包含双面、历险、合体、连体等实际结构，以基本地补足 60 张；名称直接取官方 canonical。

同时检查中文 UI、卡名、规则、类型/副类型、reminder、FRA、WPN、字体，Mountain/Opt/Hearth、双面/冒险、重印、基本地、token 排除、英中搜索及重启后重复。`fixtures/special-structures.json` 提供当前实际结构；`new-cards.json` 提供新增卡牌，若为空报告 N/A。

将**实际结果**写入当前运行目录的 `runtime-template.json` 副本，保留 `candidate_files`，填入用户原话、每项检查与五份导出路径。没有测过的项目保持 false / 未验证：

```sh
mtga-cn record-runtime --evidence /绝对路径/真实验收.json
mtga-cn install
```

`record-runtime` 验证当前临时安装哈希、实际确认、全部测试项、五份原生导出的 TitleId/数量。新增卡清单、特殊结构清单及全部 fixture 均绑定候选哈希；改掉清单不能绕过验收。只接受当前候选，历史证据不通用。导出本身仍依赖用户实际执行导入/导出；本工具不会自行伪造用户确认。验收通过后 `install` 将这次临时事务转为正式保留，回滚仍指向试装前的状态。

## Registry 和译文迁移

`state/registry.sqlite` 同时保存：

- Localization：Key/LocId、英文、中文、源文件/版本/哈希/验收范围、首次/最后验证版本、状态、字段用途、参数与格式元数据。
- Card Name Compatibility：Arena GrpId、TitleId、版本内印刷身份、中文显示、官方英文 canonical、F0/F1、既有 aliases/variants、显示与导入用途、来源、兼容状态。

Arena GrpId + 同版本官方 Cards 元数据是可用身份依据；没有伪造 Oracle ID 或声称 Arena ID 永远不变。身份/关联变化单独报高风险。仅向主正面非 token 的 TitleId 补缺失 F0，优先保留已有官方 F0；缺失时沿用历史原版纯文本 F2、次选 F1 的规则。副面/token-only 不增补；共享 TitleId 对 token/副面的影响单独统计。英文 F0 不算漏译。

自动迁移必须同时满足 Key/LocId、英文、已知用途、参数/法术力符号、格式安全、verified 来源。原文变化、新 Key、来源冲突、未知用途进入待审；未知译文保留英文。ICU plural 的可译正文与参数结构分别比较。官方卡名开头的 digital/rebalanced sprite 可按确定性规则保留在既有中文名字前；不创作牌名或规则。

优先级为显式人工修正 > 独立 AI 审查的逐项补译 > 历史已验证最终快照 > 独立审查过的现有 donor 补漏 > 普通 donor 候选。不同来源不静默覆盖：冲突内容和选择理由保存在 decisions。历史英文模式/赛制/活动名称保持英文。

如需要导入人工修正，在 `reviewed-corrections/*.json` 保存可审查文件；`update` 会读取。必须含 `review_kind: "human"`、`reviewed_by`、`source_version`、`records`；每条记录含 `layer`（card/client）、`key`、当前官方 `english`、`chinese`、registry 中准确的 `field_use`、`replaces_source_ids`。冲突来源必须显式列出。文件导入后按哈希锁定，修订请新增文件。不要把 AI 的猜译冒充人工验收。

### 待处理项的解决与持续复用

2026-10-24 后续来源复查已将 AI 审译与网络来源核实分开：所有新包使用 V2 逐项来源记录，需通过 `source_check.py validate <pack.json>`，并由独立审查绑定。使用方法与站点查询见 [SOURCE_LOOKUP.md](SOURCE_LOOKUP.md)。原先“待审为零”仅是维护决策状态，不代表每句都有现成中文。

待审核、暂不采用是需要继续解决的工作项，不能作为维护完成的理由。2026-10-24 批次已逐项处理 1,837 个记录：1,823 个中文文本槽实际更新；13 个官方空字段和 1 个技术标识保留原值。735 个未发现直接表引用的本地化槽也已补译，但不据此断言运行时不会使用。

独立 AI 审译包保存在 `reviewed-resolutions/*/pack.json`，配套 `review.json` 绑定最终包与格式兼容清单的哈希。它是独立的 AI 来源渠道，不冒充人工批准。每次构建重新核对英文、用途和身份；精确匹配才复用。人工修正继续优先，原有冲突和来源不删除。官方自身格式异常仅对经过审查的精确原文/译文对兼容，仍要求参数、标签、法术力符号和完整控制结构一致。

官方原文、用途或身份变化后必须重新调查和解决；确实缺少必要信息时，应告知具体条目、缺失信息和下一步，不应静默留在队列。审译与静态验证不等于实际游戏显示验收；新候选的安装仍遵守原有事务与客户端验收流程。

## v1.1：官方译文来源与 Oracle 审核

本次升级只改变维护器和 Registry。原有已安装资源、候选、原生验收记录和回滚事务不变。维护器代码变化后，`status` 分别显示已安装资源的历史验收与新代码的重建要求；旧候选不能拿新版代码直接再次安装。

```sh
mtga-cn audit-sources
mtga-cn audit-sources --refresh --limit 20
mtga-cn import-sources --pack /绝对路径/pack.json --review /绝对路径/source-review.json
```

这些命令只写 Registry、来源缓存和独立的 `state/source-audits/<时间>/report.json` / `REPORT.md`，不构建游戏资源。`--refresh` 每次最多读取两个登记的官方 Oracle 地址；同一天已成功且未变化的结果复用。失败、限流、内容改变或预算不足均记录缺口，不成为审核通过。未登记的卡牌不会逐张联网搜索；输出最多 20 个下一步来源工作项（可调 1–100），完整队列仅作本地分类。

来源包示例为 `state/v1.1/source-pack/pack.json`。它包含原始文档哈希、官方 URL、文档日期/日期依据、检索日期、语言变体、原文定位、英文原文及其适配说明、Arena 印刷/牌面身份、LocId、TitleId、用途与 Oracle 片段版本。必须由独立审查文件绑定来源包哈希，确认摘录、身份和适配准确；这不是人工批准译文。来源包入口拒绝 `review_kind: human`。社区和 donor 不会因此升格成官方。未知外部 Oracle ID 不猜造。

SQLite 增加 `provenance_documents`、`provenance_translations`、`provenance_reviews`、`provenance_observations`、`provenance_migrations`。原四表仍兼容。原始文档按内容哈希缓存；来源及审核只追加，UPDATE、DELETE 和替换写入不能改历史。首次迁移或补齐迁移前，用 SQLite backup 保存完整数据库并做 integrity_check；DDL 显式事务提交。备份在 `state/registry-backups/`。业务状态与来源文本分开；人工更正继续使用既有 reviewed-corrections，并保存导入凭据。旧人工更正与新官方原文或用途不匹配时，记录待审而非强行迁移。

未来 `update` 在新版官方底稿上做来源/Oracle 检查，再进入原有迁移、F0/F1 和双语导入验证；审核输入和准入相关来源状态参与候选指纹，来源审计报告参与 proof hashes：

- 已核验的官方简体中文、对应英文和用途完全匹配，所有共享 LocId 使用者身份与格式一致，且没有来源冲突，才可自动复用。
- 空白排版和直/弯引号差异可确定性处理，保留准确位置；其他标点、数字、条件或词汇变化保守待审。
- 官方明确说明只是模板澄清：记录证据支持的分类；不会由模型自动将其升级成已批准语义。
- 当前 Oracle 片段与客户端不同、同名/牌面身份不明、格式失配、繁体术语、数字专属或 Alchemy 记录，都不会自动套用实体卡中文。
- 既有人工修订保留优先级与永久来源记录；来源冲突可追溯。无可靠来源保留当前官方英文。

这里的“当前 Oracle”是**已登记并核验的具体来源版本与片段**，不是全网最新 Oracle 的自动抓取承诺。当前只接入荣光竞技场的 2024 中/英文说明和 2026 更新公告；新卡/新机制没有映射时仍列来源缺口。官方网页变化也不等同规则变化，必须重新核验摘录。`UI` 来源可以持久保存，但资源内 UI 身份尚无 v1.1 自动采纳适配器，保持 v1 原有迁移。

验证：`.venv/bin/python -m unittest tests tests_provenance -v`。真实来源验证、自动判断、原有客户端验收分别列证据；本轮没有运行 update、install 或 rollback。

## v1.2 第一轮：限定待审清理（未构建补丁）

本轮固定 20 条用途、10 条格式、10 个卡牌身份。完整结果与每条依据在 `state/v1.2-round1/REPORT.md` / `report.json`，不可变来源/用途审计追加到 Registry 的 documents/observations；这些观察不会成为人工批准或自动纳入来源选择。原始 donor、旧 decisions、荣光竞技场批准、已验收资源与回滚事务保留。

## 准入与离线预演（Pro 整体审查后的有限一轮）

```sh
mtga-cn preflight
# 也可显式选择已验收 run 的官方快照：
mtga-cn preflight --run /absolute/path/to/state/runs/<run>
```

读取指定 run 的官方快照和真实 Registry 的只读副本，在内存中重放现有批准、来源准入和生产 `decide()`。默认零联网，不构建、不安装、不改真实 Registry/历史 decisions/验收事务。报告写入新的 `state/preflights/<timestamp>/REPORT.md` 和 `report.json`，不是本机游戏此刻的运行验收。

范围包括历史 pending、新增/删除/英文或用途变化的 Key，以及带人工批准/来源绑定的 Key（后者即使原来 verified 也复核身份）。报告将历史 pending、当前可迁移、仍待审、无法评估分别计数，不读取旧诊断中的固定减数。来源发现、批准复用、格式适配是重叠维度，不相加。

人工批准中已经声明的全体共享使用者、印刷和牌面身份限制，现在在导入及每次决定中重新执行。失配不会改写批准历史，优先级不能绕过限制。相同或不适用的社区/旧版本证据不再撤销独立有效的中文；适用的同等级可信冲突仍阻止采用。`verified` 仅表示在当前证据范围可迁移，不表示官方逐字译文、全卡库人工审校或新增客户端 PASS。

既有 C10 观察可在队列中发现；“找到中文”“缓存有效”“当前身份/英文匹配”“允许采用”分开记录。观察不会自动变成可采用译文。明确未被消费的研究缓存损坏只影响该证据；已登记准入来源及人工批准依赖仍严格校验。未来获准 `update` 构建时，最终来源报告会读取该次实际 decisions。

**本轮当时的限制（后续已处理，见下一节）：**同一官方版本连续保留多个候选后，再次重建可能把上一补丁的回滚前状态当作官方底稿，Raw 哈希守卫会拒绝继续。后续已将 official_base 与 rollback_before 分开；这项修复不代表未知新版本已完成适配。

本轮任务与远端审查见 `audit-releases/admission-preflight/`。真实游戏、候选、安装与回滚保护保持原状。

## 官方底稿与回滚前状态分离（aa5b980 后单轮）

`mtga-cn diagnose-base` 只读输出五层当前哈希、manifest 哈希、官方底稿来源、回滚备份来源、旧事务标识及 `safe_to_rebuild`。它不创建锁/目录、不连接 Registry、不修改事务、不联网。`safe_to_rebuild` 只表示底稿及备份诊断通过，不是完整候选验证或安装许可。

- `official_base`：从当前 manifest 验证的原件、或确切版本且独立校验的 run/official 快照取得。不会读取 before 备份作为构建输入。
- `rollback_before`：本次安装前的真实文件，可能是上一个补丁。V2 同时保存显式字段和 V1 兼容字段；回滚只依赖这份备份，不依赖官方底稿是否仍存在。
- 旧 V1 事务只读显示 `legacy_transaction_without_official_base`，不自动补写或迁移；另行核验现有官方快照。损坏/未知事务保持阻断。
- UI 与启动字体没有 Raw 那样的官方 manifest 哈希，当前仅信任 `2026.63.20 / Steam 25640408` 的已审查本地历史捕获。信任根固定到上一轮独立审查、保护清单和 snapshot 哈希；不是发行商签名认证。完整 release 还绑定 Data/GRP、路径、manifest 和非目标资源。
- **未知新版的这两层会返回 unknown 并停建**，即使当前 Raw 已匹配。需要新增可核验的该版官方来源证据，不能靠目录名、更新 report/manifest 或旧备份绕过。此轮不添加自动获取/认证发行商底稿的功能。

生产快照、validate、preflight、创建事务均校验官方来源。当前安装资源和原验收记录未因源码升级而重建或续期；下次真正构建仍须全部原有 Validator、版本/格式守卫与客户端验收。参见 `audit-releases/official-base-separation/REPORT.md`。

## 桌面维护入口

本机桌面的 `MTGA 汉化与双语导入维护.command` 可双击打开中文菜单。选项 1 查看状态及失败原因、2 中文只读诊断、3 构建候选、4 验收后安装、5 回滚、6 操作指南；打开菜单本身不运行维护。源码在 `bin/MTGA 汉化与双语导入维护.command`，调用原有 `mtga-cn`，全部安全守卫继续生效。

官方及游戏内更新完成、退出游戏后先选 2；检查通过再选 3，完成独立审查、临时测试及真实验收记录后再选 4。可信新版底稿缺失时会停建，不能跳过验证。桌面入口依赖现有项目路径和本机 `.venv`，不附带游戏资源或数据库。
