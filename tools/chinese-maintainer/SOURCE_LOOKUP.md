# 中文来源查询与逐项核对规范

本规范适用于新译、旧译纠错、donor 迁移及 AI 补译复查。目标是让下一位维护者能重新找到依据、确认当前英文、理解必要适配，并识别尚无对应来源的部分。AI 审译通过、字体检查通过及“待审核为 0”均不能代替来源核实。

配置私有社区基线后，通过英文、身份、用途、格式和文件哈希检查的补位条目在构建中标记为 `baseline-adopted`，来源为绑定 manifest 的社区基线。它不改变下述 V2 来源枚举，不清空或改写既有审校记录，也不授予官方、人工或游戏验收状态。基线失效、差异覆盖和新增文本继续按本规范核对。

## 应去哪里找

| 来源 | 用途与查询入口 | 证据边界 |
| --- | --- | --- |
| 大陆万智牌官方站 | [cnwizards.com](https://www.cnwizards.com/)；按英文牌名、中文牌名、系列名、机制名查文章、牌图、机制介绍、更新说明 | 首选大陆官方命名与规则用语。必须保存实际文章或牌面地址；首页或搜索结果不能支持一条具体译文。 |
| 大学院废墟 | [mtgch.com](https://mtgch.com/)；按英文名、系列与编号找卡；[卡牌 API 文档及示例](https://mtgch.com/api/v2/docs)，[华袍狂欢客示例数据](https://mtgch.com/api/v2/card?set=woe&collector_number=132) | 分别读取 `zhs_card`（中文印刷文本）和 `zhs_oracle`（中文 Oracle）。印刷文本仍须核查版次与牌面；标记为 MTGZH 的 Oracle 是社区规则译文，不能写成官方中文 Oracle。字段名或结构变化时先查看实际响应和文档，不臆造字段。 |
| Scryfall | [scryfall.com](https://scryfall.com/)；英文精确名称，或 `set:woe cn:132`；检查简体中文印刷与图片、英文当前 Oracle、各面及关联物件；[API 文档](https://scryfall.com/docs/api/cards) | 聚合数据库，适合确认英文身份与寻找对应中文牌面。中文旧牌面未必等于当前 Oracle，数字专属或再平衡版也未必有中文。不能用普通版本替代 `A-` 再平衡版本。 |
| 威世智其他官方页面 | [万智牌官网](https://magic.wizards.com/) 的当前规则、机制、Arena 公告及补丁说明 | 用来核查英文变更、数字专属与再平衡行为。`zh-Hans` 页面也可能出现台湾繁体词汇或地区译名，不能仅凭语言标签认定为大陆官方译名。 |
| 已有本地来源 | 维护器登记的官方底稿、donor 版本、历史中文资源及其来源记录 | 可支持游戏专用界面、现有本地术语和格式；必须标明实际版本、槽位与哈希。历史译文自身不保证语义正确，也不能被包装成新增网络核实。 |
| 中文规则资料／裁判资料 | 只使用实际能打开、署名与更新时间可核实的规则页；保存具体 URL 和相关规则号 | 辅助解释机制、规则与术语；除非页面真的包含目标完整文本，否则只算概念依据。不要猜测站点、规则号、译文作者或访问成功。 |

例如 Reality Fracture 的大陆官方用词与其他地区页面可能不同。不得因为页面标记 `zh-Hans`，就把项目已核实的“现实裂界”自动替换成“現實碎片”；先核对大陆官方文章及当前项目证据。其他系列、专名与关键词同理。

网站收录不等于人工或官方翻译。检查返回的 `name_source`、`text_source` 等来源字段，分别确认牌名与规则文本的出处；若标记 GPT／AI／Claude／Gemini／ChatGPT，仍属于 AI 表达，不能借网站域名升级为可靠全文或概念依据。将实际声明写入 `source_declared`，未采用的记录写 `adopted:false` 并说明原因；可以留作已查证据，但不能支撑 `exact-full-text` 或 `source-backed-concepts`。未知来源也不得自动称官方，需保留不确定性并继续查找。

## 每个英文槽位的查询步骤

1. **固定当前输入。** 保存资源版本、layer、key/LocId、当前英文原文与 SHA256、用途和引用。没有直接引用的槽位也需核对，不等于可随意翻译或可断言游戏不会显示。
2. **确认身份。** 有引用的卡牌查英文名称、系列、编号、各面、数字专属／再平衡身份、token／emblem／spellbook 关联。双面牌逐面匹配；牌名、异能名、规则全文和衍生效果是不同槽位。纯数字 key 相等不足以确认对应关系。
3. **先查现成中文。** 卡牌先找大学院废墟及 Scryfall 对应中文印刷／Oracle；术语和新机制优先用大陆官方内容核实。保存查到的完整来源文本，而非仅记“网站有对应”。可按英文句子片段、旧版、各面、token、数字版等继续搜索。若 API 缺中文，不能据此断言网上不存在。
4. **比对当前英文。** 核查范围、目标、数量、时机、费用、持续时间、可选性、区域、条件及替代效果；记录来源英文与游戏英文的实际差异。旧版牌面与最新 Oracle 不同时逐项处理，不能复制后略过差异。
5. **适配游戏槽位。** 整卡来源不一定适用于整条 Arena 槽位：游戏可能拆分词条、插入参数、动态计数或加入数字版效果。只复用有对应的语义，保留游戏原有参数及格式，并记录删分句、术语统一或动态化适配。
6. **核对客户端文案。** 活动标题、活动规则、奖励、对话、教程、按钮等不能仅凭卡牌名称查找。先查同活动的官方公告及本地对应客户端资源；机制解释只能支持概念。查不到整条时标注“概念有依据，完整文案仍为 AI 表达”，不能标为“官方全文已核实”。
7. **复核并生成候选。** 检查语义与格式，逐条绑定证据。独立审查者应审查输入、证据和最终文本，不只审查“通过”标签。真实游戏显示与原生导入另行验收；候选生成不表示已经安装。

检索站点故障时，记录错误与访问时间，改查原站/API、其他来源或本地已留存证据。无法读取内容不能算已核实，搜索摘要不能替代需要完整句子的原文。继续查询后仍有缺口，列出已查站点、身份、缺的具体句段与下一步，明确告知用户并继续解决；不得静默留在待审核队列，也不得将 AI 自译改名为“来源已解决”。

## 必须保留的逐项证据

每条最终翻译记录至少包含：

- **输入身份**：资源版本、layer、key/LocId、field_use、牌名／系列／编号／面（适用时）、英文全文与哈希。
- **实际来源**：具体 URL、抓取 UTC 时间、网站与作者／维护方、语言及地区、原始响应或页面快照路径及 SHA256、所用字段与原文摘录。API 一个响应可支持多条，但每条必须指向实际对应的字段与段落。
- **匹配结论**：身份如何吻合；来源英文是否与游戏英文一致；不一致处逐项列出；印刷文本或社区 Oracle 的性质。
- **最终表达**：完整中文及哈希、相对来源的适配说明、每个仍由 AI 生成的句段和生成原因。
- **证据范围**：V2 的 `source_check.verification_level` 仅允许 `exact-full-text`（完整文本对应且差异已处理）、`source-backed-concepts`（只支持术语或规则概念）、`source-unavailable`（检索后仍未找到对应依据）、`intentional-preserved`（空字段或技术标识按原样保留）。按整条最弱的实际覆盖选择标签；混合依据须在 `audit_note`/`match_note` 中标出具体句段和 AI 剩余部分，不能用全文标签覆盖只有概念依据的句子。不得另造枚举。
- **审查与验收**：来源核对者、独立审查者与结论、技术验证记录。人类未确认就标明未确认，游戏未测试就标明未测试，不能借用旧版本验收。

原始网页/API快照、整库、带本机路径的审查包和游戏候选保留在本地或私有存储。用户认可将精简、可复用的维护数据公开到 `maintenance-data/`：保留译文、匹配身份、具体来源链接、哈希和原有来源覆盖/AI审查状态，不附带原始证据包、私人路径或账号信息。普通用户的更新包不需要这些审查材料；玩家资源分发仍走既有签名发布流程。公开数据不改变第三方归属或授予新的转载许可。

## 精简公开数据与本地证据分开

网站名称说明去哪里查，具体页面/API链接说明是哪张牌、哪一版或哪条介绍；来源类型与原站声明继续保留。只写“大学院废墟”不足以在以后英文或版次变化时重新匹配。

`maintenance_data.py export` 从已通过原始证据校验及独立来源审查的V2包生成精简数据；原始快照只在维护者本地参与导出前检查，不复制到公开目录。`validate` 在没有原始数据库的检出上检查公开文件完整性、引用和格式，不代表重新核实了外部来源，也不会生成生产采用、人工或客户端验收批准。当前生产维护器继续使用原有准入流程。

### V2 实际字段与验证入口

每行使用 `source_check` 对象，其中 `verification_level` 使用上表的四个精确枚举；`audit_note` 写覆盖范围，`english_alignment` 写当前英文与来源的异同，`adaptation_note` 写最终适配。`sources` 是数组，逐项填写 `url`、`source_kind`、`language`、`excerpt`、`excerpt_sha256`、`match_note`、`retrieved_at`（含 UTC，例如 `2026-10-24T00:00:00Z`）及 `snapshot`（`path` 为相对 pack 的真实文件路径，另含原始字节 `sha256` 和 `bytes`）。`source_kind` 仅可为 `official-print`、`community-oracle`、`official-mechanics`、`community-rules`、`community-localization`、`official-ui`、`official-announcement`、`local-existing`，按实际性质选择，不可升级来源身份。

概念依据与来源缺失行须用非空 `ai_remaining` 数组逐段披露仍由 AI 表达的部分；全文对应与原样保留不能含这种未对应句段。`source-unavailable` 另须 `lookup_attempts` 数组，每次记录实际查询 `url`、`query`、`outcome`、UTC `retrieved_at`。空字段仅用于确实空的中英源，技术标识仅保留真实标识，不得借例外隐藏普通英文。文件验证可运行 `source_check.py validate pack.json`，这只验证证据形状、哈希和覆盖标签，不替代阅读来源的语义审查。

V2 pack 的 `schema` 是 `MTGA_SOURCE_CHECKED_RESOLUTION_V2`，继续保持 `human_acceptance:false`、`runtime_acceptance:false`。独立 `review.json` 必须绑定最终 pack 及格式例外指纹，且 `source_checks_reviewed:true` 只能由实际审阅来源与适配的独立审查者出具。旧 V1 记录属于历史 AI 审译证据，不会因为兼容可读就自动变成已核实来源的 V2。

确实没有历史网络抓取时间时，不得用打包时间或文件时间填写 `retrieved_at`。只可另存 `recorded_at`（UTC）与 `timestamp_basis`（`snapshot-write-time` 或 `audit-record-write-time`）及非空 `capture_time_basis`，明确该值只是本地快照／审计文件写入时间，网络检索时间未知。原始 `retrieved_at` 若存在必须有效，不能用另一个时间掩盖错误。今后抓取应在请求实际发生时记录时间，避免继续产生这一历史限制。`lookup_attempts` 的时间字段使用同一规则。

## 格式和校验边界

必须严格保留当前英文需要的参数身份、数量与含义、ICU plural/select 分支与 offset、花括号、数字类型、HTML/TMP 标签、颜色和链接、换行控制、`CARDNAME`、法术力符号及技术标识。只有参数在语义不变且校验器允许时才能调整句中位置。不要把序号、占位参数或空源字段当成缺译填字。

当前英文自身格式异常时，保留可证明的控制结构与精确绑定的例外证据；不得关闭格式检查或对白名单全面放行。翻译来源、英文、用途、代码或候选任何一项变化，相关哈希绑定与审查结论须重建。

来源能支持“规则正确”不等于 MTGA 一定显示正确，技术测试能支持“结构未破坏”不等于译文正确。分别报告来源核对、语义复核、结构验证、真实游戏验收与安装状态。

## 已确认的缺译处理偏好

模式、赛制和活动名称保持英文的偏好不包括模式介绍。用户于2026-10-24进一步明确：例如Quick Draft名称可保留英文，但里面的玩法介绍、报名条件及奖励说明应翻译。核对字段实际作用，不能仅因Key含Title就把Desc/Description/Body介绍当成英文名称；引用表达式本身保留，按其实际引用文案核对中文。

用户已于2026-10-24明确接受：没有官方翻译的客户端专用文案、游戏提示及新风味文可以保留 AI 翻译，并明确标注 AI 来源。完成现成来源调查、英文语义与格式检查后，不必仅因缺少官方全文把这些条目无限挂为待审核。该偏好不免除卡名、规则及术语的来源核对，也不允许把 AI 文案标成官方译文。
