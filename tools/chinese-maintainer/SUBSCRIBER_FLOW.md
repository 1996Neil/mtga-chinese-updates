# 用户订阅与更新的完整流程

本文描述已核对的 v2.1 订阅客户端。GitHub Release 邮件是版本提醒，桌面客户端才负责资源更新。它不会后台自动修改游戏。

## 首次使用

1. 从项目发布页下载 `MTGA-Chinese-Subscriber-v2.1.zip` 并解压。普通使用不需要 Git、Python、Codex 或 GitHub 账号。
2. 双击「安装 MTGA 中文维护.command」。安装成功后，桌面会有「MTGA 订阅更新.command」。若已有同名入口，安装脚本不会覆盖，需核实它指向正确客户端。
3. 让 Steam 完成 MTGA 更新，打开游戏完成游戏内资源下载，再完全退出游戏。
4. 打开桌面更新入口，先「检查更新」，再「预演」。没有适配本机版本的资源时停止，不能手动选其他版本强行覆盖。
5. 预演成功后选择「应用更新」。客户端核验并重建资源，保存备份后写入目标文件。
6. 完成后启动游戏，游戏语言保持 English，查看中文显示。遇到问题先查看更新结果并使用工具提供的恢复入口。

当前公开资源只开放已验证的 Apple Silicon 组合；Intel 虽包含客户端程序，但资源兼容性尚未完成验收。首次下载的程序尚无 Developer ID 签名与公证，不能保证所有新电脑直接打开；若系统拦截，应停止并反馈，不能宣传无条件双击可用。

## 邮件订阅与 Star

想收邮件时，用户需要登录免费 GitHub 账号，在项目仓库选择 Watch → Custom → Releases，并在通知设置为 Watching 启用 Email。仅 Star 不会订阅邮件；不订阅邮件也能主动打开客户端检查更新。

可在下载入口或安装成功提示中邀请：「觉得有用，欢迎 Star 支持维护；订阅 Releases 可收到新版本通知。」Star 为自愿，不作为下载或更新条件。

## 以后每次更新

1. 用户收到新版本邮件，或主动打开工具检查。
2. 如果 Steam/游戏有更新，先完成 Steam 更新与游戏内下载，再退出 MTGA。只有汉化修订、游戏未更新时，不需要重装游戏。
3. 打开「MTGA 订阅更新.command」，选择「检查更新」。
4. 工具读取签名更新源，检查本机游戏版本、Steam build、资源状态和适配版本。
5. 选择「预演」：下载所需差分，校验并验证是否能安全应用；这一步不覆盖游戏。
6. 预演成功、游戏已退出后，选择「应用更新」。已验证的差分缓存可复用，但仍重新检查完整性。
7. 完成后启动游戏。普通资源修订无需重新下载安装客户端，也不需要 `git pull`。

GitHub 邮件不会直接更新游戏。用户漏看邮件不影响主动检查；邮件里的版本也不能替代客户端的本机兼容检查。

## 工具内部做什么

读取索引并验证签名、有效期及版本 → 选择本机兼容发布 → 获取并校验资源差分 → 根据对应基础资源重建目标文件 → 核对重建结果 → 在应用阶段保存备份并替换允许的目标文件。

下载中断可以重试，v2.1 支持断点与已验证缓存；校验失败不跳过安全检查。遇到不能识别的其他补丁或基础文件时拒绝覆盖。恢复以工具记录的上次应用前状态为准；Steam 后来更新过时须先核对状态，不能承诺旧备份可任意恢复。

资源签名用于证明更新来自发布者且未被篡改，不等于 Apple 的程序签名。普通资源更新不替换 `mtga-cn` 可执行文件；只有客户端或协议升级才需要新安装包，该类升级目前不是自动完成的。

## 维护者每次应完成什么

1. 监控提醒维护者；官方公告不等于汉化已就绪。
2. 获取可信官方资源，核对新英文、来源、身份、参数与格式，构建并完成审查及必要游戏验收。
3. 生成并签名资源清单和差分；先上传并核对发布文件，再推进签名索引。索引尚未可用前，不应通知用户立即更新。
4. 每个对外可用更新发布一个独立 Release，说明适配版本、变化、下载/更新步骤和验收范围。现有 r1/r2 共用旧预发布条目保留；发布器已要求新修订独立tag并在索引就绪后发布通知，不能把修改旧附件当成新版本通知。
5. 用户按上述桌面流程更新。正式可用与 testing 验收范围必须分清。

目前索引有效期为30天；即使没有新适配，维护者仍需按现有发布流程续签。过期或网络不可用时停止获取更新，不改写用户已装文件。
