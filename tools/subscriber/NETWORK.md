# GitHub 联网订阅维护

统一主仓库为公开的 `1996Neil/mtga-chinese-updates`，同时提供源码、维护与分发。旧源码仓库仅保留迁移历史。下载无需 GitHub 登录。固定订阅地址为：

`https://raw.githubusercontent.com/1996Neil/mtga-chinese-updates/main/feed`

用户安装一次 v2.1 客户端，以后从桌面入口检查、预演并应用你发布的匹配版本。客户端不是自动更新程序，协议升级仍需新安装包；普通游戏适配修订不需要重装客户端。

## 发布一个新适配

先使用现有维护器完成官方底稿核验、候选构建、独立审查和本机验收。不要把其他版本的验收文件复制过来。候选的 builder code 必须与验收时一致。本机简化验收只能发布 testing 渠道；stable 仍要求完整验收矩阵。

在统一主仓库执行：

```sh
zsh tools/subscriber/build.sh
zsh tools/subscriber/publish_github.sh /绝对路径/已审候选目录 2 /绝对路径/本机验收.json /绝对路径/新的发布输出目录
```

发布端需要 Python 3、Xcode command line tools、已登录的 GitHub CLI 和仓库写权限。终端参数里的修订号须大于该游戏版本之前的修订号。完整 client_version + Steam build 绑定发布身份。

私钥只在维护者本机 `~/Library/Application Support/MTGAChinesePublisher/signing/subscription-v1.ed25519`。不要提交、上传或发送私钥。备份时使用自己的安全密钥备份方式；换钥需要另行设计迁移。公钥不是秘密。

脚本依次生成签名差分 → 生成小型安装包 → 冻结并审计允许上传的文件 → 创建独立草稿 Release 并上传资源 → 核对草稿 SHA-256（缺失服务端指纹时认证下载复核） → 正常 Git push 切换并读回签名索引 → 发布 Release 通知 → 检查匿名下载入口。失败时查看输出；上传失败不会提前推进索引，并发 push 不会强制覆盖别人。可用 github_publish.py 重试同一已冻结版本，同名不同内容会被拒绝。

这是内容寻址与签名防篡改保证，**没有验证 GitHub 服务端 immutable Release 锁定**。有仓库权限的人仍可能删除资产或改 Git 内容；客户端会拒绝不匹配的内容，但无法保证服务可用性。

## 索引续期与停服

索引有效期 30 天。即使没有新适配，也需在到期前用同一已审包重新执行 `github_publish.py publish`，它保留原发布引用、增加序列号并续期；不重传已匹配资产。具体参数与首次发布相同，`--receipt` 可用新文件。不可手工改已签 JSON，不可恢复旧序列索引。

续期不是后台任务；本次没有添加定时任务。索引过期或 GitHub 不通时，客户端停止获取更新；已经安装的游戏文件保持现状。

## 验证范围

本地测试覆盖签名、路径白名单、回滚、崩溃恢复、冻结内容、上传中断、并发发布、独立草稿与索引/通知顺序，以及安装一次后同一客户端连续更新两个修订。实际数量以本次测试日志为准。本地模拟升级不等于另一台真实 Mac 验收。公网发布后另留匿名下载与正式客户端 HTTPS 读取、预演证据。

首版游戏资源使用维护者已验收的 2026.64.0 / 25763111 候选。只保留用户实际确认的中文显示、中英混合导入、导出牌张核对和重启复测结论，不扩大为全矩阵。当前游戏使用原维护器安装记录，本轮订阅工作不迁移或改写它。

客户端含 arm64/x86_64，但 Intel 运行、Developer ID、公证及干净下载 Gatekeeper 尚未验收。公开分发差分不代表获得游戏、卡牌或字体版权方的再分发许可。

下载策略：客户端元数据单次请求限180秒，资源差分每次请求限3600秒；连续90秒低于1KiB/s会停止。元数据允许有限重试；资源下载中断后保存已确认 HTTP 响应范围的断点，下次操作继续。3600秒是单次请求预算，整个操作含多个文件可能更久。所有下载仍按签名大小及SHA-256核对。

发布后的 SERVER_DIGEST_AND_ANONYMOUS_HEAD 只证明服务器记录的文件指纹与匿名链接可访问，不代表匿名下载全部字节已经通过；草稿阶段 DRAFT_SERVER_DIGEST 只证明认证 API 记录的指纹一致。正式客户端完整下载、签名/哈希校验和重建另存 network-acceptance.json；完成前状态为 testing 已发布、端到端验证待完成。服务器指纹格式异常或不符直接拒绝，不能跳过。

客户端 v2.1 在独立 patch-cache 中保存差分，每次复用都重新核对签名给出的大小和 SHA-256；索引、签名和有效期每次重新检查。缓存按修改时间淘汰，上限 2 GiB（含下载暂存预算），不会把未完成的文件用于构建。服务器忽略或拒绝 Range 时最多回退一次完整下载。预演后再应用可复用缓存。父进程被强制终止时，下载子进程继续持有状态锁，避免第二客户端并发写入。此前 v2 安装包保留，建议初次安装使用 v2.1；已安装 v2 可运行新版安装入口替换维护工具。

## 统一仓库后的发布顺序

`1996Neil/mtga-chinese-updates` 同时承载源码与分发；`main/feed` 和现有签名协议、公钥不变。新修订使用独立 `mtga-<release.id>` tag。已有签名引用的历史共享 tag 只续期，不新增附件。

草稿资源先通过 GitHub 认证 API 校验服务端指纹；若缺少服务端指纹则下载认证响应体并校验完整 SHA256。草稿没有匿名下载入口，因此此阶段不把认证校验记录成匿名网络通过。之后推进签名索引并核验精确提交中的索引，最后发布 Release 并检查匿名 URL。资源上传或索引 CAS/读回失败不提前发布通知；最终发布失败保留可重试的同一草稿与已提交索引。发布后匿名入口检查失败应报告并修复可用性，不删除用户索引历史。
